# 04-Manual-QA: Music Maker — 릴리스 전 수동 QA 체크리스트

> 작성일: 2026-05-15
> 기반: `docs/04-QA-Strategy.md` §7
> 상태: Draft v0.1
> 적용 시점: **모든 릴리스 (MVP / Beta / v1.0 / v1.5 / 핫픽스)** 직전

---

## 사용법

1. 각 섹션을 위에서 아래로 진행하되, **Critical 섹션은 누락 시 출시 차단**.
2. 각 항목은 PR 머지 후 staging 환경에서 검증.
3. 발견된 결함은 GitHub Issue로 등록 + 심각도 라벨(`S1`~`S4`) 부여.
4. 결과 표는 본 문서 끝의 **릴리스 사인오프**에 첨부.

---

## 0. 환경 사전 점검 (Critical)

- [ ] Staging URL 접근 가능 (`https://staging.music-maker.app`)
- [ ] Staging 환경변수에 **운영용 Mureka API Key 사용 안 함** (테스트 키만)
- [ ] DB 마이그레이션 적용 완료 (`alembic current` == HEAD)
- [ ] Redis 정상 연결 (`/healthz` 응답 200)
- [ ] S3/MinIO 버킷 라이프사이클 정책 적용 (30일 만료)
- [ ] Sentry DSN 환경 분리 (prod ≠ staging)
- [ ] 결제 Stripe 키가 **테스트 모드**임을 확인 (`sk_test_*`)

## 1. 실제 Mureka API로 음원 청취 (Critical)

> **자동화로 검증 불가능한 영역**: 음질, 가사-멜로디 매칭, 자연스러움

### 1.1 한국어 K-Pop

- [ ] 프롬프트: "여름 밤, 첫사랑의 설렘, 신스 팝, 120 BPM, 90초"
- [ ] 가사: 한국어 자동 생성
- [ ] **청취 체크**:
  - [ ] 보컬 발음이 명확한가 (한국어 음운)
  - [ ] BPM이 명세대로인가 (대략 ±5)
  - [ ] 구조 [Verse] → [Chorus] → [Verse]가 청각적으로 인지되는가
  - [ ] 잡음/클리핑/끊김 없음
  - [ ] A/B 두 변주가 충분히 다른가

### 1.2 영어 R&B

- [ ] 프롬프트: "Mellow R&B, late night vibes, smooth vocals, 80 BPM, 60s"
- [ ] 가사: AI 자동 생성 (영어)
- [ ] **청취 체크** (위와 동일 항목 + 영어 발음)

### 1.3 인스트루멘탈 (Lo-fi)

- [ ] 프롬프트: "Lo-fi house, rainy Tokyo, piano + soft drums, 30s, instrumental"
- [ ] **청취 체크**:
  - [ ] 보컬이 없음 (확인)
  - [ ] 분위기가 프롬프트와 일치

### 1.4 길이 경계 테스트

- [ ] 15초 (최소): 끊김 없이 완성
- [ ] 300초 (최대): 5분 초과 시 422 에러 명확히

### 1.5 음질 등급 (1~5)

| 곡 | 음질 | 가사 자연스러움 | 멜로디 | 평가자 |
|---|---|---|---|---|
| K-Pop | __/5 | __/5 | __/5 | |
| R&B | __/5 | __/5 | __/5 | |
| Lo-fi | __/5 | — | __/5 | |

> 모든 항목 평균 ≥ 3.5 미만이면 출시 보류, Mureka 모델 옵션 재검토.

## 3. 결제 플로우 (Critical)

> Stripe **테스트 모드**에서 진행. 실제 카드 사용 금지.

### 3.1 신규 구독

- [ ] Pricing 페이지 진입 → "Pro 시작" 클릭
- [ ] Stripe Checkout 정상 표시 (한국어 로케일)
- [ ] 테스트 카드 입력: `4242 4242 4242 4242` / `12/34` / `123`
- [ ] 결제 성공 후 자동 리다이렉트
- [ ] 크레딧 즉시 100 충전 (Webhook 처리)
- [ ] 영수증 이메일 발송 (Mailhog 또는 실수신함)

### 3.2 실패 케이스

- [ ] 거절 카드 `4000 0000 0000 0002` → 에러 메시지 명확
- [ ] 3DS 인증 카드 `4000 0027 6000 3184` → 3DS 챌린지 표시
- [ ] 결제 도중 뒤로가기 → 크레딧 미충전

### 3.3 구독 관리

- [ ] Billing 페이지 → 다음 청구일 표시 정확
- [ ] 플랜 변경 (Pro → Studio) → 프로레이션 정상
- [ ] 구독 취소 → 즉시 해지 vs 만료까지 사용 옵션 명확

### 3.4 환불

- [ ] Stripe 대시보드에서 환불 처리 → 크레딧 회수
- [ ] credit_ledger에 type=refund 행 추가 확인

## 4. 약관 / 개인정보 / 저작권 (Critical)

### 4.1 페이지 존재 & 표시

- [ ] `/terms` 이용약관 페이지 정상
- [ ] `/privacy` 개인정보처리방침 페이지 정상
- [ ] `/legal/copyright` 저작권 안내 페이지 정상
- [ ] 풋터에 위 3개 링크 노출

### 4.2 가입 시 동의

- [ ] 회원가입 폼에 이용약관·개인정보 동의 체크박스
- [ ] 마케팅 수신 동의는 **선택**으로 분리
- [ ] 동의 안 한 항목은 가입 진행 차단

### 4.3 저작권 문구 노출

- [ ] Studio Generate 버튼 근처 또는 결과 화면에 사용 권리 안내
- [ ] 다운로드 시 PDF 사용 권리 증명서 발급 (PRD R2)
- [ ] 보컬 클로닝 시 2단계 동의(저작권 + 신원) 모달

### 4.4 GDPR/PIPA 대응

- [ ] Settings → "내 데이터 다운로드" 버튼 동작
- [ ] Settings → "계정 삭제" 30일 유예 안내 + 처리 요청 접수
- [ ] 쿠키 배너 표시 (EU IP일 때 / 또는 전체)

## 5. 콘텐츠 모더레이션 (Critical)

### 5.1 입력 단계

- [ ] 가사 프롬프트에 욕설/혐오 표현 입력 → 422 에러
- [ ] 입력 단계 모더레이션 패턴이 한국어/영어 모두 동작
- [ ] 모더레이션 통과 후에도 출력 단계 재검사 (이중 필터)

### 5.2 사용자 신고

- [ ] 곡 카드 하단 "신고" 버튼 노출
- [ ] 신고 시 카테고리 선택 (저작권/혐오/성적/기타)
- [ ] 신고 후 토스트 "1시간 내 검토" 표시
- [ ] Admin 대시보드에 신고 큐 적재 (Beta 단계 OK이면 운영툴로 대체)

### 5.3 보컬 클로닝 (v1.5)

- [ ] 음성 업로드 전 챌린지 문장 낭독 요구
- [ ] 클로닝 음원에 비가청 워터마크 삽입 (스펙트럼 분석 검증)
- [ ] 신용카드 등록 + 본인 인증 안 한 사용자는 기능 잠금

## 6. 성능 & 안정성 (High)

### 6.1 페이지 성능

- [ ] Lighthouse 점수 (랜딩):
  - Performance ≥ 85
  - Accessibility ≥ 95
  - Best Practices ≥ 90
  - SEO ≥ 90
- [ ] LCP ≤ 2.5초 (NFR)
- [ ] Studio 페이지 초기 로드 ≤ 3초 (3G fast 시뮬)

### 6.2 생성 응답 시간

- [ ] 같은 프롬프트로 3회 생성 → P50 ≤ 50초 (NFR)
- [ ] 30분 연속 사용 중 메모리 누수 없음 (Chrome DevTools Memory)

### 6.3 SSE 연결 안정성

- [ ] 생성 중 네트워크 일시 단절 → 자동 재연결 → 진행률 복구
- [ ] 백그라운드 탭으로 5분 → 포그라운드 복귀 시 최신 상태 표시
- [ ] 동시 3개 생성 → SSE 모두 정상 수신

## 7. 사용자 경험 마이크로 검증 (Medium)

### 7.1 마이크로 인터랙션 (02-UX-Design §5)

- [ ] Generate 버튼 hover → glow 효과
- [ ] Generate loading 중 ripple 애니메이션
- [ ] 결과 도착 → 토스트 + "ting" 사운드 (음소거 모드 시 무음)
- [ ] 즐겨찾기 별 클릭 → 회전 + scale 애니메이션
- [ ] 크레딧 차감 → 우상단 숫자 카운트다운 200ms
- [ ] 다크↔라이트 테마 토글 시 깜빡임 없음

### 7.2 빈 상태 (Empty States)

- [ ] 라이브러리 비어있을 때 안내 + Studio 진입 CTA
- [ ] 프로젝트 비어있을 때 일러스트
- [ ] 크레딧 0일 때 충전 안내 모달

### 7.3 에러 상태

- [ ] 네트워크 오프라인 → 명확한 안내 + 재시도 버튼
- [ ] 5xx → "잠시 후 다시 시도" 토스트 + Sentry 자동 보고
- [ ] 404 페이지 → 라이브러리 / Studio 링크

## 8. 데이터 무결성 (Critical)

### 8.1 크레딧 일관성

- [ ] 10건 생성 시뮬레이션 후:
  - `SELECT SUM(amount) FROM credit_ledger WHERE user_id=?` 와
  - `SELECT credits FROM users WHERE id=?` 일치
- [ ] 한 건 실패 → `users.credits`가 차감 전 값으로 복원

### 8.2 파일 라이프사이클

- [ ] 30일 전 생성된 미사용 곡 → cleanup_task로 자동 삭제 확인
- [ ] 즐겨찾기/프로젝트 추가된 곡 → 30일 후에도 보존
- [ ] S3 라이프사이클 정책과 cleanup_task **이중 보장** 작동

### 8.3 메타데이터

- [ ] 생성된 모든 mp3에 ID3 태그 `produced_by=music-maker, gen_id=...`
- [ ] WAV에도 메타데이터 동등 삽입

## 9. 운영 도구 & 관측성 (High)

### 9.1 로그

- [ ] CloudWatch에서 `mureka_trace_id`로 검색 가능
- [ ] `email`, `lyrics` 본문이 로그에 마스킹되어 출력
- [ ] 시크릿 키가 로그에 절대 노출되지 않음 (grep `mk_` 0건)

### 9.2 메트릭 & 대시보드

- [ ] Grafana 대시보드 정상 표시:
  - 생성 성공률 패널
  - P50/P95/P99 응답 시간
  - 큐 깊이
  - 일 비용
- [ ] 알림 테스트 (Slack 채널 #alerts 메시지 도착 확인)

### 9.3 Sentry

- [ ] 의도적으로 발생시킨 5xx → Sentry에 트레이스 캡처
- [ ] `severity:S1` 태그 자동 부여
- [ ] PagerDuty 연동 (P1 알림 받음)
