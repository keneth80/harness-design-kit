# Reviewer 지시문 — 모바일(iOS 시뮬레이터) 검증 루프

이 문서는 Reviewer 에이전트가 Expo 앱을 iOS 시뮬레이터에서 검증하는 절차를 정의한다.
기존 웹 Reviewer 루프(Playwright로 브라우저 띄움 → DOM 읽기 → 스크린샷 → 판단)의
**모바일 대응판**이다. 부품만 갈아끼운 것이며, "스크린샷 보고 판단"하는 Reviewer의 본질은 같다.

## 언제 도는가
이 무거운 루프는 매 작업마다 돌지 않는다. `/checkpoint` 또는 명시적 검증 요청 시에만 실행한다.
매 작업의 빠른 검증(타입체크·린트·유닛테스트)은 Stop Hook이 담당한다 (CLAUDE.md의 2단계 구조 참조).

## 루프의 4개 부품

### 1. 빌드 & 설치
- `npx expo run:ios` 로 development build를 시뮬레이터에 설치한다.
- **Expo Go를 쓰지 않는다** (네이티브 QR 모듈 때문). 이미 빌드돼 있으면 재빌드 생략하고 설치된 앱을 부팅한다.
- 시뮬레이터 부팅: `xcrun simctl boot <device>` (이미 부팅 상태면 생략).

### 2. 화면 조작 (Playwright의 자리)
- 화면 탭·스와이프·텍스트 입력은 **Maestro** YAML 플로우로 선언적으로 기술한다.
- Reviewer는 검증할 시나리오마다 Maestro flow를 생성/갱신하고 실행한다.
- 좌표 하드코딩(simctl 직접 탭)은 피한다 — 화면이 바뀌면 깨지고 유지보수가 어렵다. Maestro의 텍스트·ID 기반 선택자를 쓴다.

### 3. 스크린샷 → 판단
- 각 단계 후 `xcrun simctl io booted screenshot <path>` 로 화면을 캡처한다.
- 캡처한 PNG를 Reviewer(비전) 에이전트가 직접 보고 "기대대로인가"를 판단한다.
- 판단은 추측이 아니라 **명시된 기대치**와 대조한다. 기대치는 각 시나리오에 정의돼 있어야 한다.

### 4. 테스트 QR 이미지 주입 (핵심 가치 검증)
- 시뮬레이터 사진첩에 테스트 QR을 미리 넣는다: `xcrun simctl addmedia booted tests/fixtures/<qr>.png`
- 이것이 본 앱의 진짜 가치(사진첩 이미지 디코드)를 검증하는 열쇠다. 빠뜨리면 핵심 미검증이다.
- 최소 픽스처 세트: ① 유효한 텔레그램 친구추가 QR ② 일반 URL QR ③ QR이 아예 없는 사진(빈 결과 처리 검증) ④ 흐릿하거나 일부 잘린 QR(실패 처리 검증).

## 필수 검증 시나리오 (Definition of Done과 연동)
Reviewer는 아래를 모두 통과해야 "검증 완료"로 본다. 하나라도 실패면 Dev에게 구체적 화면·기대치와 함께 반려한다.

1. **앱 부팅** — 홈 화면이 크래시 없이 렌더링되는가.
2. **사진첩 권한** — 이미지 선택 시 권한 요청이 뜨고, 허용/거부 흐름이 둘 다 동작하는가.
3. **핵심 디코드** — 사진첩의 텔레그램 QR을 선택 → 친구추가 링크가 정확히 추출되고 화면에 표시되는가.
4. **링크 연결** — 추출된 링크 탭 시 해당 앱/브라우저로 연결을 시도하는가.
5. **빈 결과** — QR 없는 사진 선택 시 크래시 없이 "QR 없음" 안내가 뜨는가.
6. **실패 케이스** — 손상된 QR에서 앱이 죽지 않고 적절히 처리하는가.
7. **공유 시트(가능 시)** — 외부 앱에서 이미지를 공유했을 때 QR-Reader가 수신·디코드하는가. (Share Extension은 시뮬레이터 검증이 제한적일 수 있으니, 안 되면 수동 검증으로 명시하고 넘긴다.)

## 사각지대 — 정직하게 보고할 것
다음은 시뮬레이터로 검증 **불가**하다. Reviewer는 "통과"라고 말하지 말고 "시뮬레이터 검증 범위 밖"으로 명확히 보고한다.

- **카메라 라이브 스캔** — 시뮬레이터에 물리 카메라 없음. 실기기 수동 검증 필요.
- **Share Extension 실제 동작** — OS별로 시뮬레이터 한계. 가능한 만큼만 검증하고 나머지는 실기기로.

거짓 통과(false pass)는 길1의 "탄탄함" 목표를 정면으로 배신한다. 검증 못 한 것을 검증했다고 하지 않는다.

## 반려 시 형식
Dev에게 돌려보낼 때는 항상 다음을 포함한다:
- 어느 시나리오에서 실패했는가
- 기대한 화면/결과 vs 실제 캡처된 화면/결과
- 관련 스크린샷 경로
- (가능하면) 재현 Maestro flow
