# Architecture Improvement Skill

코드베이스의 설계 품질을 개선한다. shallow module을 deep module로 만들고,
불필요한 복잡성을 제거한다.

## Deep Module 원칙

좋은 모듈은 **간단한 인터페이스 뒤에 많은 기능**을 숨긴다.
나쁜 모듈은 인터페이스가 구현만큼 복잡하다 (shallow module).

```
Deep:    간단한 API → 복잡한 내부 로직 (사용자는 신경 안 써도 됨)
Shallow: 복잡한 API → 단순한 내부 로직 (사용자가 다 알아야 함)
```

## 점검 포인트

1. **인터페이스 복잡도** — 함수/클래스의 매개변수가 5개 이상이면 의심
2. **정보 은닉** — 내부 구현이 외부에 노출되고 있는가?
3. **의존성 방향** — 순환 의존이 있는가?
4. **중복** — 같은 로직이 2곳 이상에서 반복되는가?
5. **네이밍** — 이름만 보고 역할을 알 수 있는가?

## 개선 프로세스

1. CONTEXT.md의 도메인 용어와 docs/adr/의 결정을 먼저 읽는다
2. 코드베이스를 탐색하여 shallow module과 높은 coupling을 찾는다
3. 개선 제안을 우선순위별로 정리 (영향 범위 × 개선 효과)
4. 하나씩 수정 — 각 변경마다 테스트 통과 확인
5. ADR로 설계 결정을 기록
