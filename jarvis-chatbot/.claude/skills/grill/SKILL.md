# Grill Skill

코딩을 시작하기 전에 질문 공세로 요구사항을 명확히 한다.
에이전트와 사용자 사이의 정렬 불일치(misalignment)를 방지하는 것이 목적.

## 언제 사용하나

- 새 기능 구현 전
- 모호한 요청을 받았을 때
- "이거 만들어줘"라고 했는데 구체적 스펙이 없을 때
- `/grill` 커맨드로 직접 호출

## 프로세스

### Phase 1: 이해 확인
1. 요청을 내 말로 다시 설명 — "이런 걸 만드는 거 맞나요?"
2. 핵심 행위(behavior) 나열 — "이 기능이 하는 일은 A, B, C인가요?"
3. 경계 조건 질문 — "X가 비어있으면?", "동시에 두 명이 접근하면?"

### Phase 2: 결정 사항 확인
4. 기술적 결정 — "어떤 패턴을 쓸까요? 이유는?"
5. 스코프 확인 — "이건 포함인가요, 아닌가요?"
6. 우선순위 — "MVP에 필수인가요, 나중에 해도 되나요?"

### Phase 3: 정렬 문서화
7. 합의된 내용을 CONTEXT.md에 반영 (새 용어가 나왔으면)
8. 주요 결정이 있으면 ADR 작성 제안
9. 구현 계획을 vertical slice 단위로 정리

## 원칙
- 모든 분기(branch)가 해결될 때까지 질문한다
- 추측하지 않는다 — 모르면 묻는다
- 사용자가 "됐어, 시작해"라고 할 때까지 코드를 쓰지 않는다
- 질문은 구체적으로 — "더 자세히 알려주세요" 대신 "X가 Y인 경우 Z를 반환해야 하나요?"
