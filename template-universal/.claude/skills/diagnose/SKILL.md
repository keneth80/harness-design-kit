# Diagnose Skill

하드 버그와 성능 회귀를 체계적으로 진단하는 루프.
추측으로 코드를 고치지 않는다 — 증거 기반으로 판단한다.

## 진단 루프

```
1. REPRODUCE  — 버그를 확실하게 재현할 수 있는 최소 단계 확보
2. MINIMISE   — 재현 케이스를 최소 크기로 줄이기 (변수 제거)
3. HYPOTHESISE — 원인에 대한 가설 1-2개 세우기 (추측 아닌 근거 기반)
4. INSTRUMENT — 로그/브레이크포인트/assert 추가하여 가설 검증
5. FIX        — 최소 범위로 수정
6. REGRESSION TEST — 이 버그가 다시 발생하지 않는 테스트 추가
```

## 원칙

- REPRODUCE 없이 FIX로 넘어가지 않는다
- "아마 이것 때문일 것 같다"로 코드를 수정하지 않는다
- INSTRUMENT 단계를 건너뛰지 않는다 — 가설을 증거로 확인한다
- FIX 후 반드시 REGRESSION TEST를 남긴다
- 수정 범위는 최소한으로 — 리팩토링은 별도 커밋

## 체크리스트

- [ ] 재현 가능한가? (재현 불가면 로그 확보 우선)
- [ ] 최근 변경과 관련 있는가? (`git log --oneline -10`, `git diff`)
- [ ] 에러 메시지를 정확히 읽었는가? (전체 스택트레이스 확인)
- [ ] 환경 문제인가? (.env, 포트, 서버 상태)
- [ ] 수정 후 기존 테스트가 모두 통과하는가?
- [ ] 회귀 테스트를 추가했는가?
