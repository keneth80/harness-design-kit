# 랜딩 페이지 구조와 문구

랜딩 페이지는 홈페이지가 아니다. 홈페이지는 여러 목적을 받아주는 로비이고, 랜딩 페이지는 한 사람을 한 문으로 안내하는 복도다.

**제안 하나 → 대상 하나 → 행동 하나.**

이 스킬은 페이지가 **무엇을 어떤 순서로 말할지**만 정한다. **어떻게 보일지**는 정하지 않는다.
시각 값은 `docs/design/brief.md` → 프로젝트 토큰 → frontend-design 스킬 순서로 따른다. 이 스킬의 어떤 내용도 그 셋을 덮어쓰지 않는다.

## 1. 사전 질문

설계나 문구 전에 아래를 모은다. 브리프·spec·README에 이미 있는 건 묻지 않고, 빠진 것만 **한 번에 묶어서** 묻는다.

- **목적**: 유일한 주요 행동(체험, 데모 예약, 구매, 대기 신청, 다운로드), 정확히 무엇을 받는지, 무엇을 전환으로 셀지
- **대상**: 누구인지, 어떤 문제를 풀려는지, 지금 전환하지 않는 이유 세 가지(반론), 유입 경로(광고, 검색, SNS, 메일), 들어올 때 이미 아는 것
- **증거**: 로고, 후기, 숫자, 사례, 스크린샷·데모 영상, 환불·해지 조건
- **제약**: 말투(친근함·격식), 모바일 비중

답을 모르면 합리적으로 가정하고 한 줄로 밝힌 뒤 진행한다. 질문 때문에 작업을 멈추지 않는다.
답은 `docs/design/brief.md`의 "8. 랜딩 페이지" 절에 적는다 (없으면 절을 추가한다). 브리프 전체가 없으면 `/harness-design:design-brief`를 먼저 제안한다.

## 2. 섹션 구조

**첫 화면 (필수)**
1. 헤드라인: 결과 + 대상
2. 서브헤드: 어떻게, 구체적으로
3. 주요 CTA: 동사 + 받는 것
4. 증거 하나: 로고 줄, 숫자, 짧은 후기
5. 대표 이미지: 제품 화면, 영상, 또는 강한 일러스트

**중간 (논증)**
6. 문제 → 해결, 한 섹션
7. 이점 3~5개, 결과 중심
8. 작동 방식 3단계
9. 사회적 증거: 후기나 사례

**하단 (반론 처리)**
10. FAQ 6~12개
11. 위험 줄이기: 무료 체험, 언제든 해지, 환불 보장
12. 마지막 CTA: 첫 화면과 같은 행동

섹션 순서와 개수는 출발점이다. 브리프의 과업이나 레이아웃 유형에 맞게 빼고 합쳐도 되지만, 첫 화면 다섯 요소와 마지막 CTA는 남긴다.

## 3. 레이아웃 유형

하나를 고르고 이유를 한 줄로 적는다.

| 유형 | 언제 |
|---|---|
| A. 클래식 (히어로 + 섹션) | 제품 화면 한 장으로 이해된다. 가장 흔함 |
| B. 긴 이야기형 | 설명이 필요하고 의심을 넘어야 한다 |
| C. 최소 전환형 | 의도가 높은 유입(기존 사용자 메일), 짧은 제안(다운로드, 대기 신청) |
| D. 비교형 | 검색 의도에 대안 비교가 있다 ("X vs Y", "OO 추천") |

## 4. 전환 원칙

- **유입과 메시지를 맞춘다.** 광고에서 오면 광고 헤드라인을 히어로에 그대로 이어 받는다. 약속과 톤이 같아야 한다.
- **다음 행동을 하나로.** 첫 화면에 경쟁하는 CTA를 두지 않는다. 보조 링크는 시각적으로 한 단계 낮춘다.
- **기능보다 이점.** 기능은 제품이 하는 일이고, 이점은 그게 사용자에게 뜻하는 것이다.
- **구체적으로.** "시간을 절약하세요"가 아니라 "주간 보고서를 4시간에서 15분으로".
- **위험을 줄인다.** 무료 체험, 무료 요금제, 카드 등록 없음, 언제든 해지, 환불 보장 중 하나 이상.
- **반론은 각주가 아니라 섹션으로.** 망설임이 큰 제안이면 FAQ를 앞으로 당긴다. 증거는 그것이 뒷받침하는 주장 바로 옆에 둔다.

## 5. 문구

- **헤드라인 틀**: "{고통} 없이 {결과}", "{대상}을 위한 {분야}", "{시간} 만에 {결과}". 틀은 출발점일 뿐, 그대로 채운 티가 나면 다시 쓴다.
- **서브헤드**: 한두 문장. 무엇이고 누구를 위한 것인지.
- **CTA**: 동사 + 받는 것. "무료로 시작하기", "데모 예약하기", "체크리스트 받기". "더 알아보기", "제출", "확인"은 쓰지 않는다.
- **이점 목록**: 굵은 이점 한 구절, 그 뒤에 근거나 세부. 예: **시안 비교가 빨라집니다.** 클릭 한 번에 레이아웃 세 가지를 만듭니다.
- 콘텐츠 사실감, 금지 상투어, 대시 금지는 `${CLAUDE_PLUGIN_ROOT}/skills/design-review/references/finish.md`의 "1. 콘텐츠"를 따른다.

## 6. 작업 순서

코드 전에 아래를 `docs/design/landing-copy.md`에 쓰고 사용자에게 보여준다.

1. 페이지 개요: 섹션과 순서
2. 히어로 문구: 헤드라인, 서브헤드, CTA, 증거 한 줄
3. 이점 3~5개
4. 작동 방식 3단계
5. FAQ 6~12개와 답
6. SEO/AEO: 색인할지 말지, 색인한다면 title과 meta description
7. 레이아웃 유형과 이유

그다음 **섹션 하나씩** 만든다: 히어로 → 이점 → 작동 방식 → 증거 → FAQ → 마지막 CTA.
매번 페이지 전체를 다시 만들지 않는다. 섹션 단위로 가야 통제가 되고 변경을 검토하기 쉽다.
다 만들면 `/harness-design:design-review`로 찍어서 확인한다.

## 7. SEO와 AEO

- **색인하지 않는다**: 광고 전용 캠페인 페이지, 기간 한정 제안. `noindex`를 붙이거나 색인되지 않는 경로에 둔다.
- **색인한다**: 상시 제안, 검색 의도가 약속과 맞는 페이지. 분명한 title과 meta description, 홈·기능 페이지에서 오는 내부 링크,
  질문과 답 형태의 FAQ(AI 답변 엔진이 인용하기 좋다), 알맞으면 FAQ 구조화 데이터.

## 8. 자주 하는 실수

- 첫 화면에 CTA가 여러 개
- "혁신", "최적화" 같은 흐릿한 가치 제안
- 결과 없이 기능만 길게 나열
- 증거가 맨 아래에 묻힘
- 모바일에서 읽기 힘든 배치
- 다음 행동이 분명하지 않음

## 체크리스트

- [ ] 제안 하나, 대상 하나, 주요 행동 하나
- [ ] 첫 화면에 경쟁하는 CTA 없음
- [ ] 흐릿한 동사 대신 구체적인 숫자
- [ ] 위험 줄이기 장치 하나 이상
- [ ] 증거가 주장 옆에
- [ ] 레이아웃 유형을 이유와 함께 골랐음
- [ ] `docs/design/landing-copy.md`를 먼저 썼음
- [ ] finish.md의 콘텐츠·상태·출시 항목 통과
