# 벤치마크 역제안

잘되는 가게에 손님으로 가서 동선과 메뉴판을 적어 온 뒤, "우리 가게엔 이걸 가져오자"를 먼저 제안하는 일이다.
주방(소스 코드)은 들여다보지 않고, 코드·문구·이미지·브랜드는 가져오지 않는다. 가져오는 것은 패턴과 동작이다.

## 1. 준비
- 인자(`$ARGUMENTS`)에서 주소(최대 3개)와 "알고 싶은 것"을 나눈다. 주소가 없으면 묻는다.
- 우리 프로젝트를 먼저 읽는다: `docs/goal.md`, `docs/spec.md`, `CONTEXT.md`, README. 아무것도 없으면 "무엇을 만들고 있나요?"만 한 줄로 묻는다.
- 사용자에게 한 번 알린다: 공개 페이지만 사이트당 최대 20쪽, robots.txt를 지키고 요청 사이 1.5초 간격, 문구·이미지·코드는 가져오지 않는다.
- 사이트의 이용약관 페이지가 보이면 WebFetch로 자동 수집 금지 문구(automated, scrape, crawl, robot, 자동, 수집)를 확인한다. 있으면 멈추고 그대로 진행할지 사용자에게 묻는다. 법적 판단은 하지 않는다.

## 2. 둘러보기
```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/bench_crawl.mjs" --check
node "${CLAUDE_PLUGIN_ROOT}/scripts/bench_crawl.mjs" --url <주소1> [--url <주소2>]
```
- 결과는 `docs/benchmark/<호스트>/site.json`과 `shots/`(커밋되지 않음). 표준 출력의 `pages`, `skipped`, `stopped`를 확인한다.
- `--check`가 실패하면 출력의 `hint`(설치 방법)를 보여주고 묻는다. 설치하지 않겠다면 **얕은 모드**: WebFetch로 첫 페이지와 메뉴의 주요 페이지 5개까지만 읽고 `docs/benchmark/<호스트>/notes.md`에 페이지별 제목·메뉴·버튼·폼 구조를 적는다. 보고서에 "얕은 모드"를 표시한다.
- exit 4(robots.txt가 시작 주소를 막음)면 그 사이트는 분석하지 않는다고 알린다.

## 3. 분석
사이트마다 Agent 도구로 `harness-full:benchmark-analyst`를 띄운다 (여러 개면 한 번에 병렬로). 백그라운드로 보내지 말고(`run_in_background: false`) 결과를 받은 뒤 다음 단계로 간다. 지시에 넣을 것:
사이트 폴더 경로, "알고 싶은 것", 우리 프로젝트 요약(3~5줄). 각자 `benchmark-report.md`를 쓰고 요약을 돌려준다.

## 4. 역제안 (사용자와 함께)
보고서(들)를 읽고 우리 프로젝트에 비춰 세 갈래로 제안한다. 사이트가 여럿이면 기능별 비교표를 먼저 보여준다.

```
가져올 것 (최대 7개)
  1. <기능 이름> — 사용자에게 주는 것 / 근거: <사이트·페이지, 판정> / 우리에게 맞는 이유 한 줄
다르게 할 것
  - <그들의 방식> → <우리 방식 제안> (이유)
안 할 것
  - <기능> (우리 목표와 안 맞는 이유)
```
- 판정이 "추정"이나 "모름"인 것은 그렇게 표시한다. 못 본 기능을 확인한 것처럼 제안하지 않는다. 소개 문구로만 본 기능은 추정이다.
- 사용자가 고르게 한다. 선택지 도구가 있으면 쓰고(4개 넘으면 번호로 답받기), 고른 것만 다음으로 넘긴다.

## 5. 남기기
- `docs/benchmark/proposals.md`: 세 갈래 제안 전체와 사용자가 고른 표시, 근거 보고서 링크, 날짜.
- 고른 기능마다 동작을 확인할 시나리오 초안을 `docs/benchmark/scenarios.draft.json`에 쓴다 (`harness.scenarios.json`과 같은 형식, 주소는 `${BASE_URL}`).
- 다음 단계를 안내한다:
  - 기획서에 넣기: `/harness-full:plan-start` (spec.md가 있으면 갱신), 또는 큰 작업이면 먼저 `/harness-full:grill`
  - 시나리오로 확정: `/harness-core:scenarios` (초안을 검토해 `harness.scenarios.json`에 합침). 구현 후 이 시나리오가 통과하면 "가져온 흐름"이 실제로 동작하는 것이다
  - 화면 방향: `/harness-design:design-brief`의 레퍼런스로 이 보고서를 쓴다 (harness-design이 켜져 있을 때)

## 하지 말 것
- 로그인, 폼 제출, 입력, 유료 영역 우회, 봇 탐지 회피
- 문구·이미지·로고·코드 복사. 보고서와 제안에는 패턴과 동작만
- 스크린샷을 공개 저장소나 공유 문서에 올리기
- 앱·데스크톱 프로그램 분석. 웹이 아닌 대상은 REA 같은 전용 도구가 설치돼 있을 때 그 도구를 쓰라고 안내만 한다
