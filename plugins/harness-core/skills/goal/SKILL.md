# 원장에 묶인 목표 루프

`/goal`은 조건이 맞을 때까지 Claude가 멈추지 않게 하고, 별도 평가자가 조건을 확인합니다. 평가자도 모델이라서
"다 됐어요"라는 말에 넘어갈 수 있어요. 그래서 조건을 **사람 말이 아니라 기계가 찍은 도장**에 묶습니다.
도장은 `verify_run.py`가 남기는 서명된 원장이에요.

## 1. 준비 확인

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/verify_run.py"
```

- `"state": "unconfigured"`면 멈추고 `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/loop_setup.py"`로 감지한 검사 명령을 보여준다.
  동의를 받으면 `--write-verify`로 적고, 감지가 안 되면 사용자에게 명령을 물어 `harness.config.json`의 `verify`에 적는다.
- `"state": "pass"`면 이미 끝난 상태다. 목표를 걸 필요가 없다고 알린다.
- 실패면 `failures`를 요약해 보여준다. 이것이 루프의 출발점이다.
- `harness.config.json`이 없으면(init 전) 시험지 보호가 꺼져 있다. `/harness-core:init`을 먼저 권하고,
  그래도 진행하면 "테스트 약화를 막는 장치가 없다"고 분명히 알린다.

## 2. 조건 만들기

조건은 짧고, 관찰할 수 있고, 상한이 있어야 한다. 기본형:

```
verify_run.py를 실행한 출력과 verify_run.py --status 출력이 모두 state "pass"다. 테스트·골든 데이터를 약하게 바꾸지 않았다. 12번 고쳐도 안 되면 멈추고 남은 실패를 보고한다.
```

- 인자(`$ARGUMENTS`)에 목표가 있으면 앞에 붙인다. 예: "결제 모듈 회귀 테스트 전부 통과. verify_run.py ..."
- 상한은 인자에 숫자가 있으면 그 값, 없으면 12. 상한 없는 조건은 만들지 않는다.
- 조건에 "통과한 것 같으면", "충분히" 같은 판단 표현을 넣지 않는다.

## 3. 걸기

- `ProposeGoal` 도구가 있으면 그 조건으로 제안한다 (사용자가 한 번에 승인).
- 없으면 사용자에게 그대로 입력할 명령을 보여준다: `/goal <조건>`

## 4. 루프 중에 지킬 것

- 한 바퀴마다 `verify_run.py`를 실행해 결과를 대화에 남긴다. 평가자는 이 출력을 보고 판단한다.
- 통과를 위해 테스트·골든 데이터를 고쳐야 할 것 같으면 멈추고 근거와 함께 사용자에게 묻는다.
  하네스가 이런 변경을 확인 창(ask)으로 돌린다. `claude -p` 같은 무인 실행에서는 거부된다.
- 원장(`.harness/verify-ledger.json`)은 직접 쓰지 않는다. 하네스가 막는다.
- 같은 실패가 두 바퀴 연속 줄지 않으면 방법을 바꾸거나 멈추고 보고한다.

## 정기 점검이 필요하면

조건을 향해 달리는 대신 일정 간격으로 상태만 보고 싶으면 `/loop 30m python3 <verify_run.py 경로> --status`처럼
`/loop`를 쓴다. `/loop`는 세션이 열려 있는 동안만 돈다.
