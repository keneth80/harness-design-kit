## 하네스 규칙

훅이 시크릿 읽기, 위험한 명령, 검사 결과 위조, 테스트 약화를 막는다. 아래는 사람이 지킬 판단 기준이다.

### 작업 방식
- 가정은 밝히고, 해석이 갈리면 임의로 고르지 말고 대안을 제시한다. 더 단순한 방법이 있으면 먼저 제안한다.
- 요청을 검증 가능한 목표로 바꾼다. "고쳐줘" → 재현 테스트를 쓰고 통과시킨다.
- 문제를 푸는 최소한의 코드만 쓰고, 요청과 연결된 줄만 바꾼다. 주변 코드를 임의로 "개선"하지 않는다.
- 주석은 "무엇"이 아니라 "왜"를 쓴다.

### 먼저 묻고 할 것
패키지 설치, 아키텍처·스키마·public API·인증·배포·환경변수 변경, 대규모 이동·포맷팅·리팩터링.

### 보안
- 키·토큰·비밀번호는 코드에 쓰지 않는다 (이름만 `.env.example`에). 하네스가 막으면 우회하지 말고 알린다.

### 통과와 마무리
- 통과 여부는 `verify_run.py`의 원장(`.harness/verify-ledger.json`)으로 판단한다. 테스트나 정답 데이터를 약하게 고쳐 통과시키지 않는다.
- 워크플로우 명령(`/harness-full:full-cycle` 등)이 없는 명령으로 보이면 대신 수행하지 말고 사용자에게 알린다.
- 끝낼 때 짧게 보고한다: 바꾼 파일, 주요 변경, 알려진 한계, 다음 추천 작업.
